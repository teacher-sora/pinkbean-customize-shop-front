# 반응형 · 틀 · 스크롤 · 서피스

## 화면 모드 = 폭 + 입력 기기

`lib/useBreakpoint.ts`(`bpOf`)가 정한다. **폭만으로 나누지 않는다** — 큰 모니터의 절반 창(약 960px)이 태블릿으로 잡히면 안 된다.

| 모드 | 조건 | 배치 |
|---|---|---|
| `mobile` | 폭 ≤ 520 | 세로로 쌓는다: 머리 → 미리보기(높이 216) → 목록 → 아래 부위 바 + 탭 바. 창은 하단 시트 |
| `half` | 521~1199, 마우스 | 2분할(목록 + 오른쪽 312px). 목록 머리는 한 줄(보기와 성별은 '보기 설정'에 접는다) |
| `tablet` | 861~1199, **터치** | 2분할(오른쪽 330px). 배치는 PC 와 같고 조작은 터치 규칙 |
| `pc` | 폭 ≥ 1200 | 2분할(오른쪽 360px), 페이지 스크롤 없음 |

- 내용의 최대 폭은 1440px, 틀의 안쪽 여백은 `16px 26px`, 머리·본문·아래 바 사이는 10px.
- 터치 판정은 `(hover:none), (pointer:coarse)`. 개발 뷰어(`/viewer`)만 `?pbtouch=1` 로 강제한다.
- hover 와 터치의 차이는 폭이 아니라 CSS 의 `(hover:hover) and (pointer:fine)` 로 가른다.
- **모바일은 줄여 놓은 PC 가 아니다.** 조작을 아래(엄지가 닿는 곳)로 내리고, 아이콘 + 글자 조합에서는 아이콘만 남긴다(배경 버튼, 광장 등록 등). 하단 탭만은 아이콘 아래에 짧은 이름을 단다.
- 카드의 세로 비율은 어느 화면이나 같다(높이/폭 ≈ 1.34, 최소 1.12). 좁아지면 비율이 아니라 **열·행 수**를 바꾼다(`ShopContext` 의 격자 계산). PC 는 6×3, 절반은 3×3, 모바일은 3×2.
- 서버가 내보내는 HTML 은 늘 PC 배치다. 화면 모드는 브라우저에서 정해진다.

## 높이와 스크롤

- PC·절반·태블릿: 틀(`frame.module.css .root`)은 `100svh` 고정, 문서는 스크롤되지 않는다. 패널 안에서만 스크롤한다.
- 모바일: 페이지 높이는 `max(100vh, var(--pb-min-h))` 이고 **문서가 스크롤된다**(브라우저는 루트가 스크롤될 때만 아래 툴바를 접는다). `--pb-min-h` 는 목록이 재서 넣는다(위아래 부품 + 카드 두 줄). 낮은 화면에서는 페이지가 길어지고 카드는 납작해지지 않는다.
- 터치 기기의 문서 스크롤 규칙(`globals.css` 의 `@media (pointer: coarse)`)은 **`body{overflow:hidden}` 뒤에** 있어야 한다. 앞에 두면 덮여서 페이지가 잘린다.
- **목록 안에 세로 스크롤을 만들지 않는다.** 목록은 쪽 단위로 넘긴다.
- `100dvh` 를 쓰지 않는다.
- 스크롤 영역에는 `overscroll-behavior: contain` 과 `.pb-scroll`/`.pb-scroll-thin`, 그리고 **`scrollbar-gutter: stable`**(스크롤바가 생길 때 칸이 밀리지 않게. 창 본문은 `both-edges`).
- 스크롤 영역에는 **`pb-fade`** 를 단다 — 더 볼 것이 남은 쪽에만 가장자리가 흐려진다. 쪽 번호가 있는 목록에는 달지 않는다(쪽 번호가 그 역할을 한다).

| 탭 | 스크롤 |
|---|---|
| 코디 · AI 코디 검색 | 쪽 넘김(PC: 휠·화살표·쪽 번호 입력, 모바일: 좌우로 미는 가로 스크롤) |
| 코디 광장 | 쪽 넘김. 모바일은 가로로 자유롭게 밀고 쪽 번호가 따라온다 |
| 코디 정보 · 염색 · 프리셋 | 패널 안 세로 스크롤 |
| 공지·건의함 | 서피스 안 세로 스크롤 |

목록의 쪽 DOM 은 **지금 쪽과 앞뒤 한 쪽만** 만든다. PC 는 트랙을 `translateX` 로, 모바일은 네이티브 가로 스크롤(트랙 폭 `쪽 수 × 100cqw`)로 넘긴다.

## 서피스 — 창은 하나다

떠오르는 창은 전부 `surface/Surface.tsx` 하나를 쓴다(연출 설정·북마크·염색·점 위치·부위 염색·미리보기 배경·VS·광장 상세·가져오기·공지). 막·패널·손잡이·머리·발이 공통이고 **안의 내용만** 갈린다. 새 창이 필요하면 `kind` 를 하나 늘리고 내용 컴포넌트를 만든다 — 창을 따로 만들지 않는다.
(닉네임으로 불러온 코디를 고르는 `shop/LookDialog.tsx` 만 따로 만든 창이다. 그 방식을 새로 따라 하지 않는다.)

- PC·절반·태블릿: 가운데 창. 크기는 종류와 무관하게 `min(900px, 앱 영역 − 40px) × min(620px, 86svh)` — 폭의 기준은 뷰포트가 아니라 **앱 영역**이다.
- 모바일: 하단 시트(최대 높이 85%. 연출 설정 · 북마크 · 미리보기 배경은 내용 높이만큼). 패널 어디를 잡아도 아래로 끌어 닫는다(70px, 손잡이는 56px. 버튼·입력·슬라이더·스크롤 중인 영역은 제외). 막에서 끌어도 따라 내려오고, 내렸다 되돌리면 닫히지 않는다. 끈 직후의 막 누름은 무시한다.
- **모바일 시트의 본문은 늘 스크롤되고 자식은 줄지 않는다**(`flex-shrink: 0`). 왜: 브라우저의 아래 바가 올라오면 시트가 줄어 배치가 깨진다.
- 시트가 열린 동안 문서를 고정한다(터치 기기: body `position: fixed`). viewport 는 `interactive-widget=resizes-visual`. 왜: 가상 키보드가 뜰 때 막 뒤의 문서가 밀려 터치가 어긋난다.
- 펼침·접힘은 높이 전환이 아니라 `translateY`(`glide.ts`·`sheetMotion.ts`). 도중에 방향을 바꾸면 지금 위치에서 이어 간다.
- 나타남·사라짐은 `translateY(10px)` + 불투명도. `scale` 금지. ✕·막·Esc 는 늘 바로 닫는다. 막을 눌러 닫을 때 그 누름이 막 아래 버튼으로 넘어가지 않는다.
- 창 안쪽 여백: PC 는 머리 · 본문 · 발 모두 옆 8px, 모바일 시트는 12px.
- 시트 안에서 내용을 옆으로 바꿔 끼울 때는 `surface/innerSlide.ts`.

## 정렬 · 여백

- 좌우 여백은 머리·가로줄·카드 격자가 **모두 같은 값**(PC 8, 모바일 12)이다. 위아래는 달라도 좌우는 맞춘다. 가로줄은 가장자리까지 긋지 않고 같은 여백만큼 들인다.
- 아이콘·글리프는 flex 가운데 정렬. margin 으로 보정하지 않는다.
- 모바일의 아래 부위 바와 탭 바는 **한 덩어리**이고 사이를 가로줄로 가른다. 탭 바는 아이콘 아래에 짧은 이름을 단다.
- 모바일 미리보기의 버튼 자리는 그대로 둔다: 되돌리기 · 다시실행은 오른쪽 위, 연출 설정 · 배경은 왼쪽 아래, 점 · 염색 · 북마크는 오른쪽 아래(한 줄로 모으지 않는다 — 사용자 지시).
- 배경(장면) 위에 글자를 직접 놓지 않는다. 글자는 패널이나 머리 안에 있다.

## PC 머리

높이 44(아래 탭 줄과 같다). 왼쪽에 로고(처음 화면으로), 오른쪽에 **도구 모음 한 칸** — 시간대 · 배경 보기 | 코디 평가 · 프리셋 복사. 버튼마다 흰 칸을 따로 두지 않고 한 칸 안에 테두리 없는 버튼으로 나란히 둔다. 채운 버튼은 프리셋 복사 하나뿐이다. 글자가 바뀌는 버튼은 나올 수 있는 글자를 같은 자리에 겹쳐 폭을 고정한다(`Swap`).
